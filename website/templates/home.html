CUA-Speedrun

How fast can a computer-use agent finish the job?

Most benchmarks only record whether an agent succeeded. CUA-Speedrun is an evaluation system that also measures how long each task takes and what its model calls cost. Every leaderboard run uses the same pipeline and virtual machine setup on Modal, a pay-per-second cloud service, and one agent interface works across OSWorld, OSWorld 2.0, CUA-World, and MyPCBench. Smaller task sets, chosen so model rankings match the full benchmarks, keep repeated runs affordable.

Same machine, same clock, any agent

CUA-Speedrun is the software that runs these comparisons. It holds the hardware, desktops, tasks, and timing fixed, so differences in time and cost come from the agent.

{% include "clock-line.html" %}
Identical hardware for every run
Agents and desktops run in separate Modal sandboxes, built from the same pinned images for every run. Open-weight models are served with vLLM on fixed L40S GPUs. Results do not depend on whose computer launched the run.
One agent, four benchmarks
An agent is a folder with an agent.py that receives 1920×1080 screenshots and sends keyboard and mouse actions, and an init.py that sets it up. The same folder runs on OSWorld, OSWorld 2.0, CUA-World, and MyPCBench.
A clock that measures the agent
Setup and scoring happen off the clock. If a desktop or sandbox fails, the task is retried. If the agent crashes, the task counts as failed. Each agent reports its model cost after every request.
Inputs that do what they say
Our test tool, CUA-AutoDebug, sends 94 keyboard and mouse inputs to an app that records what arrives. PyAutoGUI over SSH, a common setup, got 11 wrong, such as typing > when < was requested. Our runtime got all 94 right, five times each.
Smaller task sets that keep the ranking
We chose 50 of 295 OSWorld tasks so that model rankings match the full benchmark. On models not used to choose them, the rank correlation is 0.98.
An optional Fast I/O mode
Fast I/O mode (FastCUA) cuts the delay between an action and the next screenshot from about 2–3 s to 2–28 ms, to test whether agents benefit from a faster desktop. Leaderboard results use the normal mode unless marked Fast I/O.

Results we did not expect

  1. A faster environment, a slower agent. With Fast I/O on, GPT-6 Astra at low effort took 99.0 s per task instead of 89.5 s, averaged over five runs. Screenshots arrived before applications finished updating, so the agent looked again or repeated itself.

  2. Same score, four times the wait. Kimi K3, an open-weight model, at max effort matches GPT-6 Astra at high effort on OSWorld (89.6%). For every open-weight model we tested, another model scored at least as high in less time, and another scored at least as high for less money.

  3. Fewer tasks, similar ranking. A 50-task OSWorld subset, chosen so that historical scores match the full set, cuts evaluation time by 84.9%.

Evaluate your own agent

Start with an included agent or bring your own Python implementation. The toolkit prepares the desktops, runs benchmark tasks, and saves scores, timings, screenshots, and action logs. It supports OSWorld, OSWorld 2.0, CUA-World, and MyPCBench.

pip install cua-speedrun
cua-speedrun setup
cua-speedrun benchmark

setup saves your Modal credentials and API keys. benchmark asks for an agent and a task set, then shows progress. Compute uses your Modal account and model calls use your API key.

See the documentation to add your own agent, serve an open-weight model, or add a benchmark.
