Getting started

What do I need?

A computer with Python 3.10 or newer, git, and uv, plus a Modal account, and an API key for the model your agent calls. Modal runs the desktops and your agent. Compute is billed to your Modal account and model calls to your API key.

How do I install it?

git clone --recurse-submodules https://github.com/{{ repository }}.git
cd cua-speed-run
uv venv --python 3.11
source .venv/bin/activate
uv pip install -e .
cua-speedrun install
modal token new

modal token new opens your browser to connect your Modal account. Run every later command from the cua-speed-run folder.

How do I run my first evaluation?

Put your model key in a file named .env in the cua-speed-run folder, for example OPENAI_API_KEY=sk-.... Then run an included agent on a five-task OSWorld set:

cua-speedrun run --remote \
  --submission templates/codex_cli \
  --benchmark osworld-mini

It starts the desktops, runs each task, and prints every task's score and time. The last line shows the folder where the run is saved.

Evaluate a model

I'm a model lab. How do I evaluate my model?

Start from the included agent that already calls your kind of API, point it at your model, and run the four task sets used on the leaderboard.

  1. Pick the template below that is closest to your API.
  2. Set its model variable to your model. If your API is different, edit the model call in the template's agent.py.
  3. Run the four task sets listed in the next answer.
  4. Compare your numbers with the leaderboard. See how to get listed.

How many tasks run at once?

Four by default. Change it with --agents-per-evaluation N. Each task gets its own desktop and its own clock, so running more at once finishes the set sooner.

How many steps does an agent get?

Each template stops after a set number of model steps, 100 in most templates. Change the limit in the template's agent.py. Each benchmark also has its own time limit per task.

Open-weight models

How do I evaluate an open-weight model?

Use the qwen3vl template. Its init.py installs vLLM, downloads your model, and starts a server before the clock starts. Set VLLM_MODEL to your Hugging Face model and ask for a GPU:

VLLM_MODEL=your-org/your-model cua-speedrun run --remote \
  --submission templates/qwen3vl \
  --benchmark osworld-energy50-representative \
  --gpu L40S --env VLLM_MODEL

Open-weight results on the leaderboard use an L40S. Pick a larger GPU, such as A100-80GB or H200, if your model does not fit. For a private model, also pass --env HF_TOKEN. If vLLM needs a newer version for your model, change the version pins in init.py.

Why is the first run slow?

The first run installs vLLM and downloads the weights. The result is saved as a snapshot, so later runs of the same files skip this. Use --fresh-init to rebuild it.

Build an agent

What does an agent look like?

An agent is a folder with two Python files:

agent.pytimed, once per task
Runs as python agent.py <env_url> <task_instruction>. It looks at the screen, sends actions, and calls done.
init.pyuntimed, before any task
Installs packages or starts a model server. It can run more than once, so it must be safe to repeat. Use print("ready") if nothing is needed.

This is a complete agent.py, apart from your model call:

import sys
from cua_speedrun.client import Computer

computer = Computer(sys.argv[1])
instruction = sys.argv[2]

while True:
    screenshot = computer.observe()["png"]  # PNG bytes
    actions = my_model(instruction, screenshot)  # your code
    if not actions:
        break
    computer.step(actions)

computer.done()

Run it with --submission path/to/your/folder. The templates are complete working examples.

What actions can it send?

step takes a list of actions and runs them in order. Coordinates are screen pixels.

{"mouse": {"left_click": [640, 400]}}
{"mouse": {"double_click": [640, 400]}}
{"mouse": {"right_click": [640, 400]}}
{"mouse": {"move": [640, 400]}}
{"mouse": {"left_click_drag": [[100, 100], [300, 300]]}}
{"mouse": {"scroll": 3}}                  # positive scrolls down
{"keyboard": {"text": "hello"}}
{"keyboard": {"keys": ["ctrl", "s"]}}     # pressed together
{"action": "wait", "time": 1.0}

Sending several actions in one step saves a round trip each.

How do I give my agent API keys and settings?

Put them in .env or your shell. Variables ending in _API_KEY are passed automatically. Pass anything else with --env NAME. Never put keys in the agent's files.

How do I report model cost?

After each model response, print one line with the task's running total. The last line printed is the task's cost:

__CUA_SPEEDRUN_COST_V1__{"cost_usd": 0.1234, "usage": {"input_tokens": 12000}}

Can my agent use the internet?

Yes. Both files can call external APIs and download files.

What can't my agent do?

It can only look at the screen, send actions, and call done. It cannot reset the desktop, open a shell inside it, or see how the task is graded.

Add a benchmark

How do I add my benchmark?

  1. Package your tasks as a Gym-Anything environment. Each task has an instruction, a setup script that prepares the desktop, and a verifier that checks the final state. See tasks and verifiers.
  2. Add a benchmark folder with a manifest.yaml and one task.yaml per task, as shown below.
  3. Run any template on it with --benchmark benchmarks/my-benchmark.
  4. To add it to the leaderboard, {{ contact() }}.
# benchmarks/my-benchmark/manifest.yaml
name: my-benchmark
version: "0.1"
tasks:
  - tasks/first_task

# benchmarks/my-benchmark/tasks/first_task/task.yaml
task_id: my_first_task
description: Short label for this task
timeout_sec: 600
env:
  kind: gym-anything
  env_dir: path/to/your/environment
  task_id: first_task

The agent's instruction and the verifier come from your environment's task. Your verifier decides the score. The agent never sees it.

My benchmark is large. Can I run fewer tasks?

Yes. Give scripts/select_representative_tasks.py your past model-by-task scores and it picks a smaller subset whose scores track the full set. The leaderboard's task sets were chosen this way.

python scripts/select_representative_tasks.py scores.json --output selection.json

Without Modal

I don't have a Modal account.

Create one at modal.com, then run modal token new. That is the only setup Modal needs.

Can I run without Modal?

Yes, on a Linux machine with KVM. Leave out --remote and the desktops run as virtual machines on your machine, with the agent next to them.

# Let your user start virtual machines, then log out and back in
sudo usermod -aG kvm "$USER"

cua-speedrun install
cua-speedrun doctor --require local-vms --require osworld
cua-speedrun run \
  --submission templates/codex_cli \
  --benchmark osworld-energy50-representative

For an open-weight model, pick the GPU with CUDA_VISIBLE_DEVICES=0 and add --gpu L40S to record it. Leaderboard results were measured on Modal, so use Modal when you want to compare with them.

Results and data

What exactly is timed?

The clock starts when the agent receives the instruction and stops when it calls done or reaches the task's time limit. Starting the desktop, running init.py, and grading are not timed. Time spent waiting on the desktop and time spent in the agent are recorded separately.

How is the score calculated?

Each benchmark's own verifier grades the final state after the clock stops. The score is the average over the task set, with partial credit where the benchmark gives it.

How is cost calculated?

Cost is the model API cost per task, from the provider's charge or from the tokens used at the provider's prices. It does not include Modal compute.

Where are my results saved?

In the folder printed at the end of the run. It contains result.json with the summary and one folder per task with every screenshot, every action, the agent's output, and the grader's verdict. To print the scores again:

cua-speedrun score path/to/run-folder

Where can I get the leaderboard data?

Download every result as a CSV from the leaderboard. Full trajectories, with screenshots and actions, are on Hugging Face.

The leaderboard

How do I get my result on the leaderboard?

Run one or more of the four task sets on Modal. Then {{ contact() }}. Include the zipped run folder and the agent files you used.

Can you run my evaluation for me?

Not yet. For now, everything above runs on your own Modal account. The Run page will show when hosted runs open.

When something fails

A run failed. What should I check?

Open the run folder. events.jsonl shows what happened in order, and each task's folder has the agent's output. To test a fix quickly, run a single task with --task TASK_ID, using an ID from the printed results. If init.py downloads something that changed, add --fresh-init.

Where do I report a bug or ask a question?

Open an issue on GitHub with the command you ran and the error.
